# 国内电商试点执行包

日期：2026-10-02。状态：待执行；未进行商家访谈、数据接入、报价或收款。配套：[开发方案](DEVELOPMENT_PLAN.md)、[市场调研](MARKET_RESEARCH.md)。

## 1. 找谁、验证什么

先访谈5位能回忆最近一次真实活动的国内平台商家负责人/运营，覆盖至少2家店；其中争取仓储和财务参与核对。优先选择能合法导出商品、库存、活动与费用资料的团队。用户已选择国内平台店铺，但具体平台、行业和试点商家尚未确定。

核心假设：现有平台、ERP和表格之间，仍存在有成本的活动选择与资源分配缺口。不要先展示方案诱导赞同；先听他们如何工作。没有缺口就不强推新工具。以下门槛是项目取舍标准，不是代表整个市场的统计调查。

## 2. 30分钟访谈提纲

1. 请按时间顺序讲最近一次活动：谁决定参加、用什么资料、最终怎么审批？
2. 当时还考虑过哪些活动或不参加方案？为什么舍弃？请看实际表格或记录，不能分享时只记口述证据。
3. 最近一次调整排期、价格、投放或库存是什么原因？何时发现、谁处理、用了多久？没有问题也记录。
4. 平台原生功能和ERP已经解决了哪些问题？抖音营销托管等功能是否用过、是否适用于你们？为什么还用表格？
5. 活动前如何算钱，结束后如何对账？退款、补贴、达人费用分别什么时候确定？哪些费用现在拿不到？
6. 同一库存被哪些活动/渠道使用？可售库存字段是否已扣除锁定订单？补货承诺由谁确认？
7. 每次准备和维护这些资料分别耗时多少？能否用实际记录交叉核对？
8. 如果仅提供一份可复算的活动方案比较，哪些结果会改变你的决定？什么情况下完全没有用？
9. 是否愿意用一份历史脱敏资料与我们共同复算？谁能确认数据授权与口径？
10. 谁决定采购，目前替代方案成本是多少？下一次真实采购评估需要满足什么条件？不把口头愿意付费当订单。

每条发现记录：访谈编号、角色、店铺类型、活动月份、原话摘要、证据类型（文件/现场演示/口述）、现有替代方案、问题频率、影响、后续可验证动作。匿名编号足够，未经许可不录音或公开素材。

## 3. 最小数据清单

先收字段表头和少量脱敏行判断能否映射，再取完整试点范围。单店、一个来源、最多50个SKU、10个候选活动、90天计划窗口；不是要求一次接通四个平台。

| 数据 | 最少内容 | 核对人 |
|---|---|---|
| 商品/成本 | 内部SKU、售价、进货成本、费用口径及生效日 | 财务/采购 |
| 库存 | SKU、库存池、快照时间、实物/可售字段定义、已锁定占用 | 仓储 |
| 供应与其他承诺 | 确认到货日/数量、其他渠道预留、安全库存 | 仓储/运营 |
| 活动计划 | 报名/锁价/销售/履约节点、费用、叠加与互斥约束、规则来源 | 运营 |
| 需求假设 | 普通销售基准、各方案低中高需求及估计依据 | 运营 |
| 实际结果 | 脱敏订单行、实收、退款、费用和活动映射 | 财务/运营 |
| 当前工作方式 | 原有活动决策表、复盘表、已有平台/ERP输出 | 负责人 |

不需要账号密码、收件人、地址、电话。订单关联可用稳定匿名标识；原始脱敏业务资料留在经授权的私有目录，不进入公开Git和参赛包。无法确认授权的资料不接收。不支持的预售、套装、赠品等规则先排除并标出覆盖范围，不能当普通SKU静默计算。

证据登记字段：资料编号、来源系统、覆盖店铺/SKU/日期、导出时间、数据截至时间、字段定义、费用含税口径、已扣项、负责人、缺口、允许用途。规则另外保存生效日期与原文位置，后续过期要重新确认。

## 4. 历史回放到真实影子试点

1. 从2份历史活动资料检查可获得性，先选择1份字段完整的案例复算。另1份尽量作为留出检验；若不足，明确只验证一个案例，不调整模型后再称独立验证。
2. 锁定财务口径与库存语义，逐项对齐订单、退款和费用合计。所有差异列出原因或标为未解释；未解释的关键差异阻断收益结论。
3. 回放当时可见的信息：只有活动后才知道的销量/退款不进入活动前预测。没有当时库存快照，不能声称复原了真实历史可执行性。
4. 共审原方案和至少一个替代方案，记录建议、证据、采用/拒绝原因。不把回测最优方案当当时一定能实现的收益。
5. 对下一次活动做影子试点：冻结计划时间、输入版本、预算、需求假设、无活动基准、成功标准。商家自行决定和执行，不自动报名、改价或分配库存。
6. 活动期间记录实际变更、断货和补货；修改后产生新版本，不覆盖原预测。
7. 活动后先出临时复盘，退款/补贴结算成熟后出最终复盘。时间相同、SKU范围相同、成本口径相同才比较。没有可靠对照，不声称增量ROI由产品造成。

## 5. 验收与停止条件

| 检验 | 建议门槛 | 不通过时 |
|---|---|---|
| 痛点存在 | 5次访谈中至少3人给出可重现的决策问题 | 缩小人群或停止新增功能 |
| 数据可用 | 至少2家愿供合法脱敏样例，1家有口径负责人 | 先做数据梳理，不建设自动预测 |
| 计算可信 | 费用逐项可追溯、库存不重复承诺、关键合计无未解释差异 | 修正映射和定义后再比较收益 |
| 使用成本 | 记录首次整理及每次维护工时；重复使用净耗时比原流程下降20%作为试点目标 | 简化导入，或承认没有提效；不能忽略新增维护成本 |
| 决策价值 | 至少一条建议被采纳或有明确拒绝原因；负责人确认现有工具缺口 | 若现有工具足够，改为配置/流程服务或停止此定位 |
| 商业信号 | 至少1笔真实付费和二次使用信号 | 不扩展为完整SaaS，不把好评当付费验证 |

20%等数值为待商家共同确定的验收建议，并非调研所得或已达成结果。采纳建议不等于取得收益；付费一次不等于产品市场匹配。

## 6. 每次试点交付

- 输入覆盖与缺口清单、财务/库存口径确认表。
- 原计划与候选方案的活动日历、库存账、预算、贡献与低中高需求比较。
- 一页决策单：推荐原因、需要先确认的条件、主要风险、商家决定与负责人。
- 版本固定的计算明细，保证同输入可重算。
- 实际与计划偏差复盘，区分未结算、数据缺失、预测偏差、执行变化和可确认的效果。

尚缺：具体试点店铺及资料。当前可以完成合成验算和字段设计；真实访谈、授权数据和商业验收不能由合成数据代替。
