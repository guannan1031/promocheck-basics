# 后续开发与验收准备

状态：建议清单，NOT_RUN。此文件不是官方 `spec.md` 或 `checklist.md`，不作为流程完成证据。范围确认后，在 PRD/spec 阶段明确以下行为。

## 待落实的业务定义
- 建议输入列：activity_id、product_id、start_at、end_at、exclusive；名称可选。缺列和单元格缺值分别说明。
- 建议接受带明确偏移的 ISO 时间，统一为 UTC 计算，显示 Asia/Shanghai。拒绝无时区值，避免本机时区改变结果。
- 建议区间为 [start,end)，相邻端点不冲突；零长度区间阻断。
- “显式互斥”还需在 spec 定义为哪种字段语义，不能默认为任意重叠。建议 exclusive=true 表示该行不能与同商品任何并行活动共存，false/false 重叠不告警。
- 重复活动 ID 是否允许跨商品需产品阶段明确；建议活动 ID 在 CSV 内唯一，避免模糊归属。
- 人工确认不解锁数据错误；建议仅记录已阅、复核人及说明，不充当真实审批身份。
- 重新导入后失效旧检查结果和复核记录；报告保存输入指纹、规则版本、输入及结果。

## 开发切片建议
1. 合成 CSV → 解析预览 → 三类规则结果；先验证规则，再接界面。
2. 输入错误提示、复核记录、HTML / JSON 导出与重载失效。
3. 桌面/移动可读性、英文参赛说明、干净副本启动核验、实际操作录像。

## 必须验证的案例
| 类别 | 核心检查 | 预期 |
|---|---|---|
| CSV | 缺列、重复列、空文件、纯空行、行宽错误 | 明确错误，不能当“无异常” |
| CSV | BOM、CRLF、逗号引号字段、转义双引号、引号内换行 | 正确解析或明确不支持 |
| 必填 | 空白商品/活动 ID；重复活动 ID | 定位原行及字段 |
| 日期 | 无效日期、反向/零长区间、无偏移时间 | 不静默纠正日期 |
| 时区 | 不同偏移表示同一时间、本机时区变化 | 比较结果一致 |
| 重叠 | 同商品互斥重叠、不同商品、非互斥重叠、端点相邻 | 只报告定义内冲突 |
| 复核 | 留意见、改输入重查 | 不删除告警、不沿用旧确认 |
| 安全 | HTML/脚本字符串出现在字段和复核意见 | 界面及导出仅按文本显示 |
| 导出 | JSON 可解析、HTML 可独立打开、前后报告一致 | 输入/依据/版本/复核完整 |
| 全流程 | 错误样例→正确样例→人工记录→导出 | 逐步状态真实可见 |

所有测试使用自建合成数据；测试数量与结果在运行后写入，当前不填 PASS。
